# 草刈り・草取り・伐採「緑整」— ホームページ制作見本

ミツモア・くらしのマーケットで「ホームページ作成」を受注するための**制作見本**です。
**事業者・スタッフ・住所・電話番号・料金・相談例はすべて架空**です。フォームから送信しても、実際の見積もり・作業予約・事業者への連絡は行われません。

- 対象業務：草刈り／草取り／伐採（草や枝の集積・作業後の清掃は付随項目、処分は要相談）
- 構成：「困りごとを選ぶ → 作業内容を理解する → 費用の条件を確認する → 写真で相談する」
- 仕様・方針の詳細は [`CLAUDE.md`](./CLAUDE.md)、素材の出典は [`CREDITS.md`](./CREDITS.md)

## ページ

| `/admin` | 事業者向け案件管理（デモ）。一覧・詳細・対応状況・作業予定カレンダー |

## 起動・ビルド

Node.js 20 以上（動作確認は Node 22）。

```bash
npm install
npm run dev        # 開発サーバー（http://localhost:5173）
npm run build      # 型チェック + 本番ビルド（dist/ に出力）
npm run preview    # ビルド結果の確認（http://localhost:4173）
npm test           # 計算・面積換算・営業日判定の単体テスト
```

動作確認（Playwright）：

```bash
npm run build && npx vite preview --port 4173 &
node scripts/e2e-check.cjs http://localhost:4173 ./screenshots
```

84項目の必須確認（対象業務の限定、計算、引き継ぎ、希望日、写真、二重登録防止、保存失敗、直接アクセス、各画面幅、文字拡大、キーボード操作など）を自動で確認し、スクリーンショットを保存します。

## 保存仕様（デモ）

- 保存処理は `src/lib/storage.ts` に集約しています（`InquiryRepository` インターフェース）。
- 相談データは**ブラウザの localStorage** に保存します。**同じブラウザ内だけ**で有効で、別の端末・別のブラウザとは共有されません。事業者への通知もありません（管理画面にも表示）。
- 保存キーはすべて `ryokusei-demo:` で始まります。管理画面の「デモ初期化」は、この接頭辞のキーだけを削除してサンプル案件4件に戻します。
- 初回表示時に架空のサンプル案件を4件入れます（新規／確認中／見積もり提示済み／作業日確定）。
- 費用の目安からフォームへの引き継ぎは sessionStorage（`ryokusei-demo:handoff`）を使います。
- 写真：
  - サイト内のデモ写真は**素材ID**だけを保存し、管理画面で同じ写真を表示します。
  - 利用者が選んだ写真は、その画面でのプレビュー（`URL.createObjectURL`）だけに使い、**画像本体・ファイル名は保存しません**。保存するのは枚数だけで、管理画面では「デモでは写真を保存していません」と表示します（別の写真にすり替えません）。
- 二重送信防止：処理中フラグでボタンを無効化し、さらにフォームごとの送信トークンで同じ依頼を重複登録しません。
- 保存に失敗した場合（容量不足・プライベートモード等）は、完了画面に進まずエラーを表示します。
- 希望日（相談者が入力、最大3件）と確定作業日（事業者が管理画面で入力）は別の項目です。「作業日確定」にするには確定日の入力が必須で、希望日が自動で確定日になることはありません。

## 費用の目安（デモ計算）の仕様

- 架空の単価・最低作業料金・加算条件は `src/data/pricing.ts` で管理（すべて税込）。
- 自動計算は**草刈り・草取りのみ**：面積 × 1㎡あたり単価（下限〜上限）× 草の高さ係数 ×（1＋状況加算の合計）→ 100円単位、最低作業料金を適用。
- 面積・草の高さが「分からない」場合や 2,000㎡ 超は金額を出さず「写真で確認後にお見積もり」。
- **伐採は金額を算出しません**（「写真・現地確認後にお見積もり」。0円表示はしません）。面積・草の高さも使いません。
- 主な作業は1つだけ計算し、追加で相談したい作業は「個別見積もり」として分けて表示（二重加算しません）。
- 処分・運搬、エリア外の出張費は「別途お見積もり」として表示し、概算に含めません。
- 面積は内部で常に㎡のまま保持し、坪は表示のためだけに換算します（1坪＝400/121㎡）。単位を何度切り替えても値と結果は変わりません。

## 本番化で確認・設計する事項

保存先を Supabase 等に替えるだけでは本番運用できません。少なくとも次の設計・確認が必要です。

1. **保存先**：`src/lib/storage.ts` の `InquiryRepository` を実装した別クラスに差し替え（画面側は Promise ベースの API のみ使用）。テーブル設計、バックアップ。
2. **認証**：管理画面のサーバー側認証（現在の `demo` パスワードは廃止）。
3. **権限管理**：事業者・スタッフごとの閲覧／編集権限、行単位のアクセス制御（Supabase なら RLS）。相談者がほかの人の相談を見られないこと。
4. **写真の保存**：アップロード先（ストレージ）、容量・形式の制限、位置情報（EXIF）の削除、保存期間と削除方法、閲覧権限。
5. **通知**：新しい相談の事業者への通知（メール・LINE等）、相談者への受付確認の連絡。
6. **個人情報の扱い**：プライバシーポリシー、利用目的の明示、保存期間、第三者提供の有無、問い合わせ窓口、SSL、スパム・いたずら対策（reCAPTCHA等）。
7. **草や枝の処分・運搬**：一般廃棄物の収集運搬の許可の要否、自治体のルール、委託先の有無など、**このサイトでは適法性や対応可否を断定していません**。事業者に確認のうえ、サイトの表現（「処分は要相談」等）を決めてください。
8. **料金・条件**：単価・最低料金・加算条件・出張費・キャンセル規定・支払方法。見積もり無料かどうか（FAQ の表現）。
9. **事業者情報**：屋号、所在地、電話番号、対応エリア、営業日（5〜9月の日曜対応など）、資格・保険・所有機械の記載（確認できたものだけ）。
10. **外部リンク**：LINE公式アカウント・くらしのマーケット・Instagram・X の実URL（現在はデモ案内ダイアログ）。電話は `tel:` リンクに変更。
11. **写真**：素材写真を事業者自身の作業写真に差し替える場合は、写っている人・敷地の掲載許可を確認。ビフォー・アフターは同じ現場の写真で、施主の許可がある場合のみ。
12. **SEO**：noindex の解除（meta、`_headers`、`robots.txt`）、タイトル・説明文から「制作見本」を外す、実在の情報で LocalBusiness 構造化データを出力、地図の設置。
13. **デモ表示の削除**：上部・フッターの「制作見本」表記、フォームのデモ注意文、サンプル入力ボタン。

## 制作見本の紹介文（販促用）

草刈り・草取り・伐採業者向けのホームページ見本です。「伸びた草を刈ってほしい」など困りごとから選ぶ入口で、作業内容・含まれない作業・費用が変わる理由まで迷わず確認できます。草刈り・草取りは面積と草の高さから費用の目安を表示し、伐採は写真・現地確認へ案内。条件を引き継いだ写真相談フォームと、届いた相談を管理する画面も体験できます。

### 事業者向けの特徴

1. **作業内容に応じた相談項目**：草刈り・草取りは面積（㎡／坪）・草の高さ・傾斜など、伐採は木の高さ・本数・建物や電線との距離など、作業ごとに必要な項目だけを聞きます。「作業名が分からない」「面積が分からない」でも相談でき、問い合わせの取りこぼしを減らす流れです。
2. **写真相談の体験**：スマホで撮った写真を最大5枚まで添えて相談する流れを体験できます。費用の目安で選んだ条件と概算はそのままフォームに引き継がれ、希望日は休業日や重複を自動でチェックします（デモでは写真は送信・保存されません）。
3. **案件管理**：受付番号・相談内容・写真・希望日を一覧で確認し、「新規」から「完了」まで対応状況を更新できます。確定した作業日は希望日と分けて管理し、カレンダーで予定を確認できます。
